# Bundled reference data and redistribution

Public source history, source archives, container images and desktop installers must not include commercial database inventories, vendor characterization tables, imported database files, backups or derived inventory caches. Users supply these separately under their own authorization. Import adapters, independently authored identifier mappings and synthetic test fixtures may remain; their presence does not authorize redistribution of the underlying database. Release checks inspect archive contents and the final payload inventory, not only filenames or Git ignore rules.

The current source candidate targets Nebula LCA public commit `958c51b8d58480b32b1f0fa76bdce9c4dbad4941`. The local Compose candidate declares that revision in `deploy/engine.env`; its actual source is the operator's `NEBULA_LCA_SOURCE_DIR`, which must be verified as a clean checkout of that revision before building. Updating this declaration does not update an existing container. All engine reference files named below are tracked at that commit. Nebula One's Apache-2.0 license covers its application code and authored seed structure, not third-party data. The desktop excludes the legacy unit XLSX, full Flow CSVs and Process ZIP, retains three byte-exact metadata rows for its steel Flow identities, and installs exact Flow versions through public APIs. The explicit selected bootstrap profile initializes those compatibility catalog rows and the two required unit groups before importing exact Flow versions, preserving seed identity checks. See [retained per-version source declarations](RETAINED_SOURCE_DECLARATIONS.md) and the [desktop data inventory](DESKTOP_DATA_INVENTORY.md). Each binary retains its own exact source manifest and acceptance record.

The historical TianGong 1.0 reference foundation was already bundled in the original Nebula LCA public release: `ILCD_Unit_Groups.xlsx`, both Flow CSVs and `tiangong_processes.zip`. The [official TianGong database repository](https://github.com/linancn/TianGong-LCA-Data/blob/1ee8a1827dace69700b64354adc53cc9660177ac/README.md) publishes a [database-level MIT licence](https://github.com/linancn/TianGong-LCA-Data/blob/1ee8a1827dace69700b64354adc53cc9660177ac/LICENSE), copyright 2023 linancn. Its complete notice and fixed source reference are bundled in engine `data/Tiangong/LICENSE.TianGong` and `NOTICE.md`, and copied into the API image and desktop licence inventory. Individual records need not repeat this database-level licence. The previous exclusion based solely on 3,980 records lacking licence fields is withdrawn. The original archive is restored byte-exact, SHA-256 `fe5acc26f8a693a6ac221cae284e29972bd366fbe82ca5b50008721469f06222`, with the existing seed/import path and default reference initialization preserved.

This source commit pins the licence evidence, not a claimed match between current upstream `release.json` and the historical TianGong 1.0 archive. JRC/ILCD, EF 3.1 and newly exported platform records retain their own attribution and source declarations. Commercial ecoinvent data are not included or covered by this MIT notice.

After CRLF-to-LF normalization, the generated `flow_index.csv` and `lcia_factors_sparse_ecoinvent.csv` exactly match the bundled Flow and factor hashes above; the latter is packaged as `lcia_factors.csv` and retains its BOM. The [Commission reuse notice](https://commission.europa.eu/legal-notice_en) permits attributed reuse of EU-owned content under CC-BY-4.0 unless a specific notice or third-party rights provide otherwise.

The Compose image copies the EF 3.1 CSVs because the engine needs all three to resolve exact indicators and flows. These CSVs are method/reference data, not ecoinvent LCI background inventories. Neither this repository nor the local acceptance run establishes a blanket right to redistribute transformed JRC reference files or TianGong records. The [TianGong data guidance](https://www.tiangong.earth/en/methodology) explicitly directs users to check each version's source and licence. Confirm the applicable redistribution terms with the data owners before uploading images or publishing these data files; keep the exact file hashes and attribution with any approved distribution.

Commercial ecoinvent processes, LCI vectors, and licensed provider method packages are absent. A user who has those assets can import them into Nebula LCA separately; a foreground-only steel PCF remains partial until a pinned background solve actually contributes.

## Public TianGong electricity supply

The optional steel initialization includes Process `eec0e09b-6fd5-41c9-9a12-41300c9e6cfa@01.01.014`, fetched from TianGong open data on 2026-09-30. Its source record content hash is `8905eab87c04475a1a461085157d460a4db0e2880b9cec97a14b9ee67437fe61`; the adjacent full Process snapshot file SHA-256 is `e2d6f0ffe963575294d158124a3bc8b4059637154908c54b5dedaca43de746fc`. The source's publication section declares copyright `false` and licence `Free of charge for all users and uses`.

The editable supply model retains all four source outputs: reference electricity, fossil CO2, nitrogen oxides and sulphur dioxide. It imports the exact versioned Flow dependencies into Nebula LCA and records their FlowProperty and UnitGroup versions. Quantities come directly from the pinned inventory; no characterization factors are added by the seed. The original inventory declares a partly terminated system. Its operational electricity contribution is usable as a background association, but does not establish complete supply-chain coverage or a CBAM electricity factor. The source inventory and licence statement remain bundled beside the projection.

Authored steel intermediate flows also receive immutable versioned catalog records derived from the reviewed original seed. Initialization preserves the original seed bundle, graph and catalogue identities, rejects conflicting content, and replays existing exact versions without overwriting user edits.

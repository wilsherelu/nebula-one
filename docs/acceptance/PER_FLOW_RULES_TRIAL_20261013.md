# 逐过程、逐流核算规则试用

入口：工艺模板卡片的“核算方法”。新建方法选择核算目的，在“过程与流规则”中先选过程，再选该过程的流，点击“单独设置该流”。逐行选择纳入／排除、位置角色、Scope 1–3 和 CBAM 标记。保存为新版本，再到“检查与版本”校验。模板来源规则校验后可随新模板版本定稿；新项目获得独立草稿副本。

有过程默认规则时，逐流规则覆盖默认值，“恢复过程默认”删除覆盖。数据保存后形成新 revision，可在方法列表选择旧方法的明确版本，复制到当前版本再校验。该入口不静默取 latest，也不改写旧结果。新建默认目的为产品碳足迹；custom 目的尚未绑定执行任务时明确提示，不把它冒充 PCF。

## 已验证

在现有 `18938` 共享栈中，真实浏览器从空方法创建 `UI CO2 CH4 trial`，选择一个过程的两条气体流，设置 CO₂ 纳入、场内、Scope 1，CH₄ 排除，保存为 v2 并校验通过。点击“按该规则计算”后，结果页显示 Scope 1 为 10 kg CO₂-Eq、用户排除 2.98 kg CO₂-Eq，完整前景模型结果仍为 12.98。Scope 2、3 在此例没有贡献，显示“—”。快照 `677c6bc4-9ae9-4699-ab8d-ec80eb6fdf19` 保留精确方法身份。

真实数值脚本 `scripts/live_gas_boundary_acceptance.py` 在共享栈和单机鲜库都验证三种边界：全纳入 12.98、仅 CO₂ 10.00、仅 CH₄ 2.98；需求翻倍后批次总量 25.96，单位产品强度不变。脚本完成 16 项数值断言，原模型清单不因排除而改变。因子从运行库回执获取，不在 One 硬编码。人工测试排放量不代表实测设施数据或 CBAM 合规结果。

前端全量 49 文件、296 项通过；类型检查及生产构建通过。相关后端 64 项通过；新增公开流及已有打包边界测试通过。过程默认只对相同方向、相同贡献类型的流生效，电力输入不会继承场内排放的 Scope 1。并非 LCA 全量回归通过声明。

本轮浏览器发现并修复了纯前景状态 `foreground_only` 缺少文案导致的结果页空白。API 数值验收和 UI 创建、保存、校验、计算、读回分别记录，不把合成测试称为真实引擎通过。

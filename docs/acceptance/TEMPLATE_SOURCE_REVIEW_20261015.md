# 内置钢铁模板来源核验（2026-10-15）

核验基线：One `0ec1e3a`，方案集 1.1.5，结构模板 1.1.4，原始钢铁种子 1.1.0。本次由 Codex 直接检索公开网页并读取本地资产、独立复算；不是 Pro 审查结果，也没有重跑浏览器、求解器或发布验收。

## 结论

**2026-10-15 用户确认后的口径修正：** 产品主线采用自定义生命周期范围1–3归集，允许将购电生命周期贡献纳入自定义范围2。GHG Protocol只是明确选择该标准时的对照方案，不是对所有用户方法的强制约束。下文对GHG方法的限制仅适用于 `organization_period_inventory`；不能据此否定已有 `organization_lifecycle_carbon` 或阻止用户归集。当前生命周期方法1.0.10保持不变。本轮新增GHG对照方法1.0.6补全烧结和连铸两处购电，默认方案集升为1.1.6，原1.1.5按原字节归档，结构模板1.1.4不变。

当前模板可以作为有明确假设的教学和方法配置示例。六条直接 CO₂ 的算术可重现，当前 CBAM partial-review 1.0.7 对烧结矿间接排放和证据缺项的处理方向与欧委会指导一致。但是，原始种子包含已被新方法纠正的边界表述；组织 GHG 方法的购电选择集也不覆盖全部购电端口。因此不能给“全部模板正确、正式核算完整”的结论。

## 发现及处置要求

### P1：原始种子仍有失效的监管解释

`boundaries/cbam.json` 将电力整体排除，称内部烧结/铁水不是前体，并把未建模煤气外送后的结果称为保守上界。`acceptance/expected-values.json` 也把间接电力标为 absent_by_clause。这些解释与上述2026钢铁指导不一致。

当前 `src/nebula_one/resources/official_methods/cbam-steel-partial-review-1.0.7.json` 已显式保留烧结电力、联合监测条件、煤气和净化缺项，并拒绝上界声明。因此本次发现是**原始资产与当前方法的解释冲突**，不能据此声称当前程序把完整CBAM算错，也不能继续把原始期待值的完整SEE标签当法律依据。

后续以新种子/方法版本更新解释和覆盖声明，保留旧资产字节及历史回放；旧1940.739734仅作为已建模直接分项。增加默认模板→方法→导出的断言：烧结电力待合格因子、连铸电力按最终产品口径排除、缺联合监测或废气证据时完整值为空。用户变体必须标识自定义边界，不能因数值可算就声称正式CBAM符合性。

### P1：正式组织 GHG 方案的购电集合不完整

`ghg-organization-period-model-1.0.5.json` 的 `scope2_purchase_exchange_ids` 只有 `continuous-casting::grid-electricity-in`，而模型还有 `ore-sintering::grid-electricity-in`。`analysis/organization_period.py` 对背景映射集合做精确相等检查，因此两处供电同时绑定时可能被拒绝；不能将只含一处的集合解释成完整购电边界。

下一实现应新建方法版本，同时纳入两处真实消费端口，更新方案集精确引用并保留历史包。发电口径证据要求继续保留；不得为了通过而把任意LCA电力总量当范围2。验收需覆盖两端口、共享供应商不合并消费身份、合法缺证据、用户排除仅改对应贡献、旧版本重放。

### 口径说明：保留自定义生命周期范围1–3

自定义生命周期方法允许把完整购电路径贡献归入范围2，这是用户选择的核算口径，不是产品缺陷。仅在声称采用GHG Protocol的方案中，才适用该标准的generation-only要求。保留现有逐过程、逐流纳入/排除和重分组；不强制拆分用户选择的电力生命周期贡献，也不改变既有结果。结果仍需标明所用方案，且同一贡献不能重复计入。天工2022资产声明为部分终止清单，数据覆盖须逐来源判断。

### P2：公开电力因子数值正确，但用途有限

`public_supply/china-grid-co2-2023.v1.json` 的0.5306及引用核对通过；其CO₂-only、非完整PCF、非自动合格CBAM因子限制应继续保留。没有把2023因子改成当前年份，也没有把另两个表中的0.6096/0.8273混用。天工精确远端版本/许可本次未重新认证，不能算作在线同步验收。

## 发布门

本次完成的是来源核验和独立直接碳收支，不是完整发布验收。完成上面P1修正及回归后，才重建0.1.1供用户验收。PCF完整性仍依赖明确系统边界、全部重要背景和分配；接入一条真实电力背景只能证明链路有效。完整企业Scope3还需要类别覆盖与活动证据。不得把缺项改成零，也不要求用户替开发侧提供一份凭空的“正式账本”。

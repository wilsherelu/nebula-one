# 核心开发逻辑：一个模型，多种可持续核算

本文是 Nebula One 的公开架构约定。后续功能、界面和方法包沿用本约定；它描述职责与开发方向，不代表所有计算场景已经验收通过。历史阶段计划与本约定冲突时，按本约定实施，历史证据保持原样。

## 从建模到分析

用户在 Nebula LCA 中建立工厂或企业的工艺网络，定义过程、流、连接、参考产品和功能单位。标准化模板也是这样的模型，附带允许编辑的数量字段、兼容背景关联及适用方法。

Nebula One 读取一个精确版本，在图上按过程填写原料、能源、产品、排放和废物数量，选择兼容的背景数据集。当前工作台固定过程、流和工艺连接结构；改变结构应回到 Nebula LCA 建模，保存新版本后重新接入并验证方法适用性。

计算链路为：

**固定源模型 → 更新清单数量与背景关联 → 按核算目的派生计算模型 → Nebula LCA 求解 → One 归组、报告与追溯。**

年度宏观量与单位产品量必须声明各自基准。同一期间的过程投入产出按一致基准填写，不能将已是年总量的清单再乘一次年产量。

## 两个项目的职责

| 层 | 负责内容 |
| --- | --- |
| Nebula LCA | 工艺图建模、流与单位身份、背景供应链展开、按适用规则执行产品分配、构建过程供需 A 矩阵、清单求解和环境影响计算 |
| Nebula One | 固定模型接入、数量填报、兼容背景关联选择、版本化核算方法解析、计算模型派生、请求编排、结果归组及报告 |
| 模型与方法包 | 标准工艺结构、可编辑字段、过程与流分类、边界、分配要求、因子引用、适用条件及验证案例 |

One 通过版本化公开 API 调用独立的 Nebula LCA 服务，不复制引擎源码或另写矩阵求解器。配套安装可以固定经过验证的引擎版本，并统一启动入口；编辑器和 One 必须连接同一引擎。运行依赖不等于合并两个仓库或共享数据库。

## 按目的处理模型

过程 UUID 和流 UUID 是分类依据的一部分。同一流可出现在多个过程和交换中，所以规则还必须识别过程实例、端口、交换方向、数量单位、连接与组织归属，不能只按流名称匹配，也不能仅凭一个 UUID 全局删除或去重。

规则可以选择过程、选择排放交换、断开特定背景关联、保留外部投入数量，或者保留整个网络而对贡献路径归组。派生操作不覆盖源模型。产品分配、替代抵扣和背景展开须服从本次目的；不能先做一次普通 LCA 分配，再将总结果直接套成所有应用的结果。

| 计算目标 | 处理方式 |
| --- | --- |
| LCA／产品碳足迹 | 按所选生命周期边界、分配及评价方法保留或展开背景，计算相应环境影响；报告实际覆盖范围 |
| CBAM | 按商品和生产边界选择适用过程与排放交换，执行前体、电力、煤气等专用规则；适用电力因子独立于普通电力生命周期因子 |
| LCA 一致型组织碳核算 | 按组织控制边界和外部供应路径归组；厂内直接 GHG 特征化贡献归范围 1，外购电、蒸汽、热、冷的生命周期贡献归 LC-Scope 2，直接采购燃料上游及其他已选价值链路径归 LC-Scope 3 |
| MFA | 按求解后的过程清单、内部连接和系统边界展示物质或能源流，分别核对单位与守恒，不能将不同物理量混加 |

组织方法是 Nebula 自定义的生命周期归组，不冒称 GHG Protocol 或 ILCD 官方范围定义。内部产品转移不额外增加供应链排放；内部实际生产、运输或燃烧过程仍计算排放。同一外部投入采用背景展开或等价供应商因子之一，不能重复计入。详细约定见 [组织生命周期核算方法](LC_SCOPE_ORGANIZATION_METHOD.md)。

## 官方模板与开放扩展

钢铁等官方模板与配套方法作为可版本化的参考包交付。分类名单、因子、规则及适用声明放在包内，执行代码负责通用操作和验证。用户或开发者可以扩展模型、数据和方法，但应新增版本，不能改写既有身份。

标准模板优先使用可核验的权威流身份，尤其是基本流。跨 TIDAS／ILCD 数据源与背景库的关联需要明确的映射、量纲换算和精确供应商引用，不能靠同名替代。商业数据可由用户在许可范围内本地接入，公开仓库不分发商业清单、矩阵、缓存或受限导出。

框架发布不要求替所有用户补齐全生命周期或全部价值链类别。应区分“本次边界外”“已选且已计算”“已选但缺数据”：边界外项目不阻止所选边界合计，缺失项不默认为零。计算结果只能使用与实际覆盖相符的名称。

## 开发与验收约束

每次计算保留源模型、数据修订、背景关联、方法及因子包的精确版本与内容哈希，记录目的、派生图和实际发送依据。历史重读不解析 `latest`，也不自动重算。

开发首先打通同一模型的数量修改、背景替换、按目的派生、求解和报告。验收检查修改是否影响应变化的分项、是否保持被排除分项不变，以及保存、重读、导出是否使用同一身份。纯函数、合成接口、真实引擎和浏览器证据分别声明；方法条件的声明与哈希用于追溯，不等于软件自动完成法规核查。

这份架构文档、开发约束和可公开的参考方法纳入 Git。机器路径、凭据、私人研究材料、运行数据库和受限数据不属于公开架构文档；依其用途留在本地配置或忽略目录中。
